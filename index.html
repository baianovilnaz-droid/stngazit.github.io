Ниже — готовый вариант сайта «Плакатория»: яркая цифровая стенгазета, где посетители могут публиковать заметки с картинками и ставить лайки. Сайт будет состоять из одного файла index.html. GitHub Pages разместит этот файл, а Supabase будет хранить публикации и изображения. Для подключения Supabase в браузере используется клиентская библиотека через CDN. (supabase.com)(docs.github.com) 1. Создай проект в Supabase Создай проект на сайте Supabase. Открой SQL Editor → New query. Вставь туда весь код ниже и нажми Run. -- Таблица публикаций create table if not exists public.wall_posts ( id bigint generated by default as identity primary key, content text not null, image_url text not null, likes integer not null default 0 check (likes >= 0), created_at timestamptz not null default now() ); -- Включаем защиту строк таблицы alter table public.wall_posts enable row level security; -- Выдаём посетителям только чтение и добавление публикаций. -- Напрямую менять лайки или удалять публикации им нельзя. revoke all on table public.wall_posts from anon, authenticated; grant select, insert on table public.wall_posts to anon, authenticated; grant usage, select on sequence public.wall_posts_id_seq to anon, authenticated; -- Удаляем старые политики с такими именами, если SQL запускается повторно drop policy if exists "Anyone can read wall posts" on public.wall_posts; drop policy if exists "Anyone can add wall posts" on public.wall_posts; -- Все могут смотреть публикации create policy "Anyone can read wall posts" on public.wall_posts for select to anon, authenticated using (true); -- Все могут добавить заметку с подписью create policy "Anyone can add wall posts" on public.wall_posts for insert to anon, authenticated with check ( char_length(btrim(content)) between 1 and 300 and char_length(image_url) between 1 and 1000 ); -- Функция увеличивает лайк в базе, не позволяя браузеру напрямую -- задавать произвольное количество лайков create or replace function public.like_wall_post(p_post_id bigint) returns integer language sql security definer set search_path = '' as $$ update public.wall_posts set likes = likes + 1 where id = p_post_id returning likes; $$; -- Функцию можно вызвать с сайта, но нельзя использовать права -- владельца функции для других операций с таблицей revoke all on function public.like_wall_post(bigint) from public; grant execute on function public.like_wall_post(bigint) to anon, authenticated; RLS-политики задают, какие операции посетителям разрешены; для файлов в Supabase Storage настраиваются отдельные политики. (supabase.com)(supabase.com) 2. Создай хранилище для изображений В панели Supabase открой Storage. Нажми New bucket. Назови bucket точно так: wall-images Включи настройку Public bucket. По желанию установи лимит размера файла, например 5 MB. Сохрани bucket. Открой SQL Editor → New query, вставь и запусти: drop policy if exists "Anyone can upload wall images" on storage.objects; create policy "Anyone can upload wall images" on storage.objects for insert to anon, authenticated with check ( bucket_id = 'wall-images' ); Публичный bucket позволит показывать загруженные изображения по ссылке. Политика выше разрешает загрузку файлов именно в wall-images. (supabase.com)(supabase.com) В этой учебной версии публикации и загрузка доступны любому посетителю сайта. Для закрытого сайта или публичного проекта с незнакомыми посетителями лучше добавить авторизацию и ограничение публикаций. 3. Получи данные для подключения В Supabase найди Project URL и publishable key. В зависимости от интерфейса ключ может также называться anon key. В код сайта нужно будет вставить именно публичный клиентский ключ. Не вставляй service_role или secret key: их нельзя публиковать в браузерном коде. (supabase.com) 4. Создай файл index.html Скопируй код ниже в файл с именем index.html. Замени две строки ВСТАВЬ_... на Project URL и публичный ключ из Supabase.
